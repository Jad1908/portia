One table's meaning: its summary, every column with the role recorded for it and
its quality flags, and everything anyone has written down about it. No statistics.

Cheap, and the first thing to read about any table you are about to use. Enough
to judge whether a source is relevant, which columns could be keys, and how two
tables might relate. Start here when the one-line index in your brief is not
enough.

Two things ride along when they exist, and both are there so you do not have to
remember to ask:

- 'notes': dated sentences earlier chats left about this table, oldest first.
  Read them before you define anything on it. A note saying the outcome column
  is a grade is the difference between a label and a column of zeros.
- 'findings': what earlier chats asked this table with a query and what it
  said, grouped by the table on the other side, capped, with the total stated.

'source' is an indexed source or a MODEL this project builds, by name. After you
record a step, describe the model it built: that is how you check the table is
what you meant before anything reads it.

It describes ONE table and says nothing about what that table connects to. When
the question is which table you should be reading, ask `graph_lookup` first and
come back here with its answer. For the numbers, climb to `profile_source`.
