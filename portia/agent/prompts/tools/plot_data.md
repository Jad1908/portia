Draw a chart in the window: one SELECT, and a Vega-Lite spec over its columns, on a tab of its own.

Use it when the user asks for a picture, and when the answer to a question is a shape: a distribution, a trend, more categories than a sentence carries. Three numbers are a sentence, not a chart.

`question`, `inputs` and `sql` are as in `query_data`. `tab` is the name on the tab and the chart's identity: drawing again under the same name replaces the chart, a new name opens a new tab. `vega` is a Vega-Lite spec you write, marks, layers, scales, colours and axes all yours; portia supplies `data` from the SELECT and a field's `type` when you leave it out. Every channel names a column the SELECT returned. The aggregate, the bin, the time unit and any computed value go in the SQL under a name, because a number a chart computed is one no query returned; `aggregate`, `bin`, `timeUnit`, `calculate`, `transform` and the other computing keys are refused. `geoshape` and `image` cannot be drawn.

Unless the question says otherwise: one measure per chart; bars sorted by value, or in the axis's own order when it is time or ordinal; a title that says what is counted and over what; units on the axis; a legend only when colour carries a category; the tab named for the question. Draw one chart per message unless two are asked for.

What comes back is a receipt: the tab, `result` (the kept rows, as `query_data` keeps them), how many rows were plotted, and for a small chart the plotted rows under `plotted`. For a bigger chart `unpaired: true` gives each encoded column on its own, categories and range, without which goes with which; write what that supports, or ask `query_data` for the rows. `shown` says whether a window showed it; without one, the chart waits for `portia ui`. You have not seen the picture. `view_chart`, where offered, is how you look; a number never comes from the picture.
