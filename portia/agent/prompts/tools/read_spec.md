One spec as recorded, without running it: layer, target, the sources it declares, the models it reads and that read it, whether its compiled SQL is current, one row per step (id, op, inputs, and the n_rows, n_cols, flags and drift last measured), and its findings.

Use it before adding a step to a spec you did not write this turn, when the user asks what the pipeline does, and before naming a model as an input. Every spec is listed under Pipeline in your brief. `step` reads one step in full by its id; the ids are on the card, and a spec's name is not a step id. `finding` reads one finding by the path the card lists, with up to {finding_queries} of its queries. `match` filters steps by id pattern. `measured: true` adds the built table's shape and flagged columns; for its columns, `describe_source` or `profile_source` on the model's name. For today's numbers, `run_spec`. A card lists up to {spec_steps} steps and {spec_findings} findings.
